## [Unreleased]

### Added
- **Steam store/community links fill in instantly** — `SteamLibraryImporter.BuildDefaultLinks(appId)` generates the links that depend only on the appid (Steam Store, Community Hub, Discussions, Guides, News, PCGamingWiki) with no network call, so a fresh import shows the Links section complete from the first render (new imports get them in the metadata; existing Steam games get them merged on load via `ApplySteamLocalArtwork`). The Steam API later adds the same links plus Achievements/Workshop — `ApplyMetadata` dedupes by URL, so nothing duplicates.
- **The last-selected library view is remembered** — `ViewModeSettingsStore` saves the active view (List/Grid/Table) to a small text file under AppDataPath; `MainViewModel` restores it on startup (`_viewMode` initializes from the store) and persists it whenever the view changes, so reopening Bridge comes back to the view you were using.
- **Cinematic screenshot gallery in the Details view** — `Bridge/Controls/ScreenshotGallery.cs` (+ `.xaml`) shows the game's full-resolution Steam screenshots (`Game.Screenshots`, populated by `SteamMetadataProvider` from `data.screenshots[].path_full`): a large main image floating over a frosted backdrop of the same screenshot, a drag-to-scroll thumbnail strip, counter, arrow buttons, keyboard navigation (←/→/Esc), click-to-expand into a full-window dark overlay with its own thumbnail strip, and auto-advance every 4s (paused on hover/fullscreen, only with 2+ screenshots). The main image scales proportionally to its container via the new `FractionConverter`. Only shown in the Details view; the column is a JSON list (mini-migration `EnsureColumn("Screenshots")`).
- **Compact screenshot strip in the covers info panel** — `ScreenshotGallery.CompactMode` hides the header and large main image, showing only a thumbnail strip of smaller tiles (110×62 vs 150×84). Tapping a thumbnail jumps straight to the fullscreen overlay (`OpenFullscreen`, extracted from the main-image click). Auto-advance never runs in compact mode. Rendered at the top of the covers info panel, just under the hero, above the Details fields.
- **Covers view info panel redesign** — the compact side panel (opened by the covers' hover Info button) now stacks its content differently: the hero image fades into the panel background (`#CC1B2132`, matching the panel's own background) via a stronger gradient so the buttons stay legible with no hard edge; the game title is larger (22px, bold) with a stronger drop shadow; a favorite star sits inline after the title (`InlineUIContainer` inside the `TextBlock`, so it follows the title onto its wrapping lines) with the same gold/filled look and press "pop" as the Details hero star, persisting on real clicks only; the Play/More/Edit row moved up onto the hero (below the title), the close "X" is a theme-colored square button in the top-right corner, and the link list now wraps into two columns.
- **Covers hover cards get rounded corners** — `Border.ClipToBounds` ignores `CornerRadius`, so the cover image square edges poked out of the rounded selection ring. A new `RoundedRectClipConverter` (a `MultiBinding` of the card's `ActualWidth`/`ActualHeight` → a `RectangleGeometry` with the card's radius) clips the image to the same rounded shape. Also applied to the Details view's hero cover (`DetailsCover`).
- **Covers hover shows a bigger title and a longer Play button** — the hover overlay's game name grew (16px, up from 13) with more wrap room, and the hover Play button is wider (140px). The Details hero's Play/More/Edit buttons also got larger text/icons.
- **The covers hover Play button is now a full Play/Stop button** — it reuses the Details hero's animated template: scales on hover/click (1.08 in / 1 out, 0.92 press + bounce back), and when the game runs it switches to `StopGameCommand`, turns red (`Bridge.StopBrush`) and shows a Stop icon+label, reverting when the game closes. Same for the covers info panel's Play button (there the `IsRunning` triggers bind to `SelectedGame.IsRunning`, since that panel's DataContext is the `MainViewModel`, not the game).
- **Hero background "cover-by-width" rendering** — `FadeImage.CoverByWidth` sizes the hero art to always fill the window's full width (height = width/aspect, vertical excess clipped by the parent's `ClipToBounds`), so Steam's `library_hero` and any other ratio show edge-to-edge with no side letterbox bars, whatever the window size.
- **Smooth hero cross-fade** — the `FadeImage` transition between games now keeps each frame at its own aspect-based size and fades the outgoing frame to 0 before removing it (no hard edge when switching between different-ratio artworks), with per-frame bottom fades only for frames shorter than the hero so the frosted blur edge stays consistent.
- **Epic Games support** — `Bridge.Import/Epic/` detects installed Epic games from the launcher's local files (`LauncherInstalled.dat` + `.item` manifests), filters out Unreal Engine/DLC/plugins, and launches via `com.epicgames.launcher://` (tracked by directory, like Steam). The icon is extracted from the installed game's `.exe` (Playnite's approach — Epic has no icon service). Epic games also get **automatic metadata by name search** (`DownloadMissingMetadataByNameAsync`, via the IGDB Worker chain) instead of the appid-based lookup Steam uses — matching Playnite's decision to avoid Steam-by-name for Epic-only titles.
- **Own Cloudflare Worker as the IGDB backend** — `Bridge.Infra/igdb-proxy-worker/` + `BridgeIgdbProvider` give Bridge IGDB metadata with zero user configuration, using the same architecture Playnite uses (credentials on a server, never in the app). The Worker is the first metadata provider; Playnite's public proxy, a user-configured IGDB key and Steam-by-name are fallbacks in that order. See ADR-13.
- **Playnite's public IGDB proxy as a fallback** (`PlayniteIgdbProvider`) — used only if our own Worker is unreachable.
- **Scan Automatically redesigned and much smarter** — the installed-games picker is now a `FluentWindow` with Mica and a card list, and the detection itself was rebuilt: (1) **better names** — a candidate's display name comes from the exe's product name when it reads like a title, otherwise a compact/camelCase name is split into readable words (`DaysGone` → "Days Gone", `AlanWake` → "Alan Wake") with technical engine markers dropped (`NARUTO-Win64-Shipping` → "NARUTO"); (2) **duplicate collapse** — several executables that report the same name in the same install folder (MGS V's `mgsvmgo`+`mgsvtpp`, The Last of Us II's `tlou-ii`+`tlou-ii-l`) collapse into a single entry (the largest binary), so the picker never shows two rows for one game; (3) **already-imported detection** — a candidate is hidden as already imported if its executable path matches an existing File play action, if it lives under an existing game's install directory (catches games whose product name differs from the library name, e.g. "Murdered" vs "MURDERED: SOUL SUSPECT"), or if its normalized name matches — with the reason logged; (4) **way more junk filtered** — installers, uninstallers, redists, crash reporters (`crashpad_handler`, `crs-*`, `CrashSender`), runtimes (`nw.exe`/NW.js, `msedgewebview2`), anti-cheat launchers (EasyAntiCheat, BattlEye — matched even when the product name spaces them out as "Easy Anti Cheat"/"Battl Eye"), Rockstar/Ubisoft launchers and helpers, benchmarks, tweaker tools, and helper scripts (`.bat`) are all excluded.
- **Scan Automatically pulls metadata automatically, Steam first** — after the picker adds games, `MainWindow.ScanInstalled_Click` calls the new `MainViewModel.DownloadMetadataForAddedGamesAsync`: each added game searches Steam by name first (a manually-installed copy of a game that exists on Steam — Risk of Rain 2, Fallout 3 — gets its full Steam metadata: cover, hero, screenshots, store links), and only falls back to the IGDB chain when Steam has no match. Steam-sourced results are enriched with IGDB social links like the manual Download Metadata action. The manual game stays fully editable (no appid is written, so it never becomes Steam-managed) and keeps its local exe icon.
- **Scan Automatically shows a loading indicator** — while a scan runs, a `ProgressRing` appears in the header with "Scanning..." and the scan buttons (Detect Installed / Scan Folder / Browse) disable so the user sees the work in progress and can't start two scans at once; the scan itself runs off the UI thread so the window never freezes.
- **The app has its own themed message dialog** — `MessageDialogWindow` replaces the stock Windows `MessageBox` (which ignored Bridge's theme) with a borderless, transparent window: the rounded card (accent icon, card background, separator border) floats over the app with a soft drop shadow and `SizeToContent` so it stays compact. `MessageDialogWindow.Show` / `ShowConfirm` / `ShowAsync` drop in wherever `MessageBox.Show` was used; the Scan Automatically flow (skip notice, scan errors, "No games selected") already uses it.
- **Steam name search no longer grabs an unrelated first result** — the store's search can rank a completely different game first ("Genshin Impact" → "Dream of Corpse Lady", appid 2842800 — Genshin isn't on Steam at all), and `SteamMetadataProvider.SearchAppIdAsync` used to accept the first `<a data-ds-appid>` without checking the title, pulling the wrong game's metadata. It now tokenizes the searched name (dropping filler like "the"/"of" but keeping numerals — "2" in "Risk of Rain 2", "V" in "GTA V" — so it still tells a sequel from the original) and only accepts a result whose title contains every searched word; if none match it returns null and the caller falls back to the next provider (IGDB). Covered by `SteamSearchTitleMatchTests`.
- **Startup scrolls to the selected game** — when Bridge opens with the last-played game selected (it can be hundreds of rows down), the Covers (Grid) view now `ScrollIntoView`s the selection so the chosen cover is actually visible instead of leaving the list scrolled to the top with an out-of-view selection. Also applied to the List view (the list box got a name, `GamesList`), and it re-scrolls on every selection change — covering the first-run case where the initial selection is only assigned after the startup import finishes. Reuses the same Dispatcher-deferred scroll the covers Info panel already used.
- **Each library view remembers its scroll position** — `ScrollPositionSettingsStore` saves each view's vertical offset (List/Grid/Table) to `scrollpositions.txt` under AppDataPath (same tolerant, never-crashing pattern as `ViewModeSettingsStore`). `MainWindow.SwitchView` saves the outgoing view's offset and restores the incoming view's saved offset when you change views, and `RestoreScrollPosition` brings Bridge back to where you were scrolled on open — instead of resetting to the top each time (replacing the earlier selection-re-assertion approach, which re-rendered the covers and flickered).
- **Switching views keeps the selection** — collapsing one view and showing another could drop the visual selection (each view's `SelectedItem` binds TwoWay to `SelectedGame`). All three view switchers now re-assert the selection (`ReassertSelection`: a null→game cycle that pushes it back into the visible control). The Grid case was trickier: its one-column `ItemsSource` workaround writes `SelectedGame = null` into the VM via the TwoWay binding, so the selection is captured *before* the cycle and restored after. The workaround itself now runs **once per session** (a flag) instead of on every switch back to Grid, which used to re-render the whole cover wall and cause a visible flicker/jump each time.
- **Fixed context-menu commands in the More menu** — the menu lives in a Popup outside the visual tree, so `ElementName` bindings never resolved; commands now bind through the window's DataContext set in `MenuButton_Click`.

### Fixed
- **The Table view's Name column no longer starts pinned narrow** — `TableList_SizeChanged` clamped the available width to a 100px minimum, which permanently shrank the auto-fill Name column to that minimum when the table first laid out. It now skips the pass when the available width isn't a sane positive value (mid-layout at startup, or while the detail panel collapses) and lets the next `SizeChanged` adjust with real dimensions.
- **Startup scroll-to-selected only applies to the Grid view** — `ScrollToSelectedGame` used to call `GamesList.ScrollIntoView` in the List view too, forcing premature layout at startup that mis-sized the Table's auto-fill Name column. It now scrolls only the Covers (Grid) view; List/Table restore their saved scroll position instead (`ScrollPositionSettingsStore`).
- **The active filter/sort/group can no longer be visually unticked** — a checkable `MenuItem` toggles its own `IsChecked` on click even when the bound source value didn't change (clicking the already-active "All" unticked it while the filter stayed on). Each menu's click handler now re-asserts `IsChecked` on every sibling entry from the clicked tag (`ReassertMenuChecks`).
- **Covers in the top row no longer clip at the container's top edge on hover** — the cover card scaled around a hard-coded `CenterX=100/CenterY=150`, so as zoom changed the growth pushed above the viewport and got cut. The card now scales from its real center (`RenderTransformOrigin="0.5,0"` keeps the top edge fixed), and the `CoversList` got more top padding.
- **Buttons in the Details hero no longer get cut off by the cover when the window is shrunk** — the Play/More/Edit row (`CompactButtonsRow`) was a horizontal `StackPanel`, so when the window got narrow enough the cover (fixed 170px height) left less space than the buttons' minimum widths, overflowing underneath it. The row is now a `WrapPanel`, so the buttons wrap onto additional lines instead of being covered.
- **Manual navigation pauses the screenshot gallery's auto-advance for 5s** — after changing the shown screenshot with the arrows, thumbnails or ←/→ keys, the carousel holds its position for 5 seconds before starting to slide again, so the screenshot the user picked isn't immediately replaced.
- **The Details hero's favorite star tucks behind the cover and slides out on hover** — the star moved from the title row to the cover's left side, hidden behind its edge (translated into the cover, which renders on top). Hovering the cover slides it into view (180ms ease-out) so it can be clicked; once favorited it stays visible and fills in gold (`SymbolIcon.Filled`), unchecking while not hovering tucks it back away. Clicking it plays a short bounce "pop" (0.5→1.35→0.9→1.0 over ~380ms), and a 250ms debounce + `IsHitTestVisible` toggle prevents the star from flickering near the cover's edge.
- **The hero Play button becomes Stop while a game runs and kills it** — `Game.IsRunning` now raises `PropertyChanged` (like `Favorite`), so the Details hero's button switches between **Play** (icon+text) and **Stop** (fixed light-red `Bridge.StopBrush`) via a DataTrigger, binding to `PlayGameCommand` or the new `StopGameCommand`. `GameLauncher.Stop(game)` kills the running processes: for directory-tracked games (Steam/Epic/launchers) it kills every process under the install directory (path + executable-name fallback for elevated launchers), for tree/exact-tracked games it kills the launched PID's expanded process tree. Stop also cancels the tracking loop so the session finalizes immediately (`GameStopped` → `IsRunning=false`) — the button always reverts to Play even if the kill fails. **Fixes for fast-play/quick-stop races**: the process-tree tracker's wait-for-launch is now a poll loop (a single check ended the session before the game appeared), if Stop is pressed before the game's process has spawned a 15s background `KillWhenAppearsAsync` watcher kills it the moment it appears (otherwise the game opened right after Stop, untracked and unstoppable), and the idle grace period is now **launch-aware**: 20s while the session is under 30s old (a gap right after Play is the launcher still spawning the game — slow right after the app starts, which used to cut the session a few seconds in), dropping to 5s once the game has been running so the close is still detected quickly. Applied to both directory and process-tree tracking.
- **Launching a game during the startup metadata sync no longer flips the Play/Stop button back to Play** — `GameRepository.ResetTransientFlags` ran on every `GetAll`/`Get`/`FindByExternalId`, and the background metadata sync calls `GetAll` right after a game starts, resetting its live `IsRunning` flag to false (and re-persisting it) — the hero button snapped back to Play mid-game even though the tracking kept running. `IsRunning` is now excluded from `ResetTransientFlags` (it's a live launcher flag); the stale-`IsRunning` crash recovery (a prior session force-closed mid-game) moved to `MainViewModel.LoadGames`, which runs once at startup before the user can launch anything. Test updated to assert `IsRunning` is preserved on `GetAll`.
- **Startup selects the last played game instead of always the first** — `MainViewModel.SelectInitialGame` picks the game with the most recent `LastActivity` (persisted when a game is launched) so reopening Bridge resumes where you left off; on a completely fresh library (nothing played yet) it falls back to the first game. Pure helper, unit-tested in `ViewModels/MainViewModelInitialSelectionTests.cs`. **Fixed two follow-up bugs**: `RefreshListDisplay` now captures the selected game *before* removing it from the collection (the RemoveAt fired `CollectionChanged` and WPF cleared `SelectedItem` → `SelectedGame` became null before the old `if (SelectedGame == game)` check, so re-imports and the metadata sync dropped the selection a moment after it appeared); and on a truly first run (empty DB) the initial selection now runs again after the startup imports populate the library.
- **Epic games now get their screenshot gallery from IGDB** — the own Cloudflare Worker now requests `screenshots.image_id/screenshots.url` on its game query, and `BridgeIgdbProvider` maps them to `GameMetadata.Screenshots` (upgraded to `t_1080p`, same as Steam's `path_full`), so the Details gallery appears for Epic/IGDB games too instead of only Steam ones.
- **Steam games import their real playtime** — `SteamLocalPlaytimeResolver` reads Steam's locally-recorded playtime from `userdata\{steamid}\config\localconfig.vdf` (`Playtime` in minutes + `LastPlayed` unix under `Software\Valve\Steam\apps`), merged across accounts (max playtime, latest activity). `SteamLibraryImporter` fills it into the imported metadata, and the import applies it on new games and merges it on existing ones (never shrinks what Bridge already tracked). Zero-config, local-only, matching ADR-11 — same philosophy as the Steam local artwork resolution.
- **The More menu toggles favorites and drops the no-op Save Changes** — "Save Changes" only re-persisted already-saved data, so it's gone; the menu now shows a dynamic **Add to Favorites / Remove from Favorites** entry (`ToggleFavoriteCommand`) that persists immediately and stays in sync with the hero star. `Game.Favorite` now raises `PropertyChanged` (the entity implements `INotifyPropertyChanged` for that one property) so a programmatic toggle updates the bound star.
- **Edit button only appears when hovering More/Edit, not Play** — the hero's Edit button now reveals on the `MoreEditHost` (the More+Edit group) instead of the whole button row, so hovering over Play (or the area to its left) no longer pops Edit out.
- **The hero Play button has a press animation** — clicking it sinks the button to 0.92x then bounces back to 1.0x (`BackEase`), on top of the existing hover scale; the button is also `Focusable="False"` so clicking Play no longer steals keyboard focus from the list.
- **Closing a game no longer deselects it** — `OnGameStopped` re-renders via `GamesView.Refresh()` + `RebuildDetailedRows()` + re-asserting `SelectedGame` instead of removing/re-inserting the game from the collection (which dropped the ListBox selection).
- **Launcher-based games keep tracking after the launcher exits** — Genshin (and other launcher-driven games like Epic/GOG frontends) launch a small `launcher.exe` that spawns the real game and closes; Bridge used to track only the launched PID, so the session ended the moment the launcher died (~5s). File/Emulator play actions now use **process-tree tracking** (`ProcessTreeSnapshot` enumerates every process + its parent via the Win32 Toolhelp32 API; `ProcessTreeExpander` + `TrackProcessTreeAsync` keep the launched process *and every descendant* in the tree each poll, pruning dead ones) — the launcher exiting no longer ends the session, which survives until the real game closes. Pure tree logic is unit-tested in `ProcessTreeExpanderTests`; the OS snapshot was verified end-to-end with a real launcher→child process pair.
- **Directory tracking handles protected launchers and UAC gaps (Genshin)** — Genshin's real launcher (`HYP.exe`/`HYPHelper.exe`, HoYoPlay) runs elevated. Two fixes: (1) `Process.MainModule.FileName` *throws* (Win32 access denied) for elevated processes instead of returning null, so the original single try/catch swallowed the exception and the name-fallback never ran — the path is now read in its own try/catch, and when unreadable the process is matched **by executable name** against the install directory's `.exe` files (recursive, built once per session), mirroring Playnite's `MonitorProcessNames`; (2) an already-launched session only ends once the directory stays empty for a **10s idle grace period** (`DirectoryIdleTimeout`), covering Genshin's UAC relaunch (the non-elevated launcher exits while the user approves the admin prompt, then relaunches elevated) — otherwise the session lasted only as long as the user took to approve the UAC. The name fallback was verified live against the running HYP processes (all 5 matched).

### Fixed
- **The startup metadata sync no longer re-downloads what's already there** — previously a Steam game with a description but a missing IGDB social link was re-downloaded *in full* from the Steam API on every app open (just to fetch the link). `DownloadMissingSteamMetadataAsync` now splits the work: games missing a description get the full Steam metadata (+ IGDB links); games that already have a description only get a light IGDB call for the missing social links. `ApplyMetadata` also gained an `overwrite` flag — the manual "Download Metadata" action still refreshes every image, but the automatic sync (`overwrite: false`) only fills cover/background/screenshots that are missing, keeping already-downloaded art stable.
- **Steam-imported games are read-only in the editor except their artwork** — `GameEditViewModel.IsSteamManaged` (an appid as `ExternalId`, non-manual) drives the edit window: the General and Details tabs are hidden entirely and only the Media tab shows (icon, cover, background — with Browse/Search web still working). `Save()` writes back only the three artwork fields for Steam games; metadata (name, description, scores, genres, ...) stays managed by the startup sync. Epic and manual games keep full editing. A banner explains the restriction.
- **Directory tracking handles protected launchers and UAC gaps (Genshin)** — Genshin's real launcher (`HYP.exe`/`HYPHelper.exe`, HoYoPlay) runs elevated. Two fixes: (1) `Process.MainModule.FileName` *throws* (Win32 access denied) for elevated processes instead of returning null, so the original single try/catch swallowed the exception and the name-fallback never ran — the path is now read in its own try/catch, and when unreadable the process is matched **by executable name** against the install directory's `.exe` files (recursive, built once per session), mirroring Playnite's `MonitorProcessNames`; (2) an already-launched session only ends once the directory stays empty for a **10s idle grace period** (`DirectoryIdleTimeout`), covering Genshin's UAC relaunch (the non-elevated launcher exits while the user approves the admin prompt, then relaunches elevated) — otherwise the session lasted only as long as the user took to approve the UAC. The name fallback was verified live against the running HYP processes (all 5 matched).

### Known issues
- **Covers view shows a single column the first time you enter it on a fresh library** — after wiping AppData and launching for the first time, switching to the Grid view realizes the covers list with its *default* ItemsPanel (a `StackPanel`), not the `CenteringWrapPanel` defined in the XAML — so all covers stack in one centered column (verified by dumping the visual tree: `ItemsPresenter > StackPanel > ListBoxItem(W=1219)`). It only corrects itself after a zoom change, closing/reopening, or when the view was already Grid at startup. Root cause still open — suspected: the list is realized while the startup import is still mutating `GamesView`, so the `ItemsPanelTemplate` never gets applied on that first realization. **Current workaround**: `SetViewModeGrid_Click` re-assigns `CoversList.ItemsSource` (null → restore → `UpdateLayout`) at `ApplicationIdle`, which forces the ListBox to re-apply its `CenteringWrapPanel` and wrap the covers into columns (brief one-column flash, then correct). To revisit: investigate why the first realization ignores `ItemsPanelTemplate`, likely around `VirtualizingStackPanel`/template realization timing during the startup import.
- **Hero cross-fade blur edge pops when switching tall→short backgrounds** — in the Details view, switching from a tall game background (height ≥ the 510px hero) to a short one shows the short frame's bottom fade snapping in once the cross-fade completes instead of revealing smoothly. Left as-is for now (pre-fading both frames up front + not clearing the hero's outgoing Source already fixes the worst of it); full detail and candidate fixes in `DEVELOPMENT.md` under the screenshot gallery section.

## [0.2.0] - 2026-08-12

### Added
- **Three view modes** — the main content area switches between **List** (list + collapsible detail panel), **Covers** (a cover wall where hovering a cover reveals **Play** and **Info** buttons over the artwork) and **Details** (a flat `ListView`/`GridView` with columns: Name + icon, Release Date, Genre, Last Played, Time Played, Library, and Play/Info actions). Switched with the title bar icon toggles (`ViewMode` enum; a ComboBox before the Fase 7 overhaul).
- **Compact info panel** (`CompactInfoPanel`, inline in the main window) — opened by the hover **Info** button (in Covers view) using the hovered game, not the list selection; shows the hero, icon, name, buttons, all details and description. `PlayGameCommand` now takes the game as an optional parameter so covers/rows can launch their own game.
- **Grouping in the library list** — group by 21 fields ("Don't group" + Name, Library, Developer, Publisher, Platform, Genre, Installation Status, Completion Status, Time Played, Play Count, Install Size, Install Drive, Last Played, Recent Activity, Release Year, Date Added, Date Modified, Community/Critic/User Score). Uses `ListCollectionView.GroupDescriptions` fed by a pure, unit-tested `GameGroupResolver` (buckets for playtime/install size/scores, reference names via lookups); the list shows group headers.
- **Search, filter presets and sorting in the library list** — a name search box (case-insensitive substring), filter presets (`All` / `Favorite` / `Most Played` / `Recently Played`, combinable with the search), and sort by field + direction (22 fields: Name, Time Played, Play Count, Last Played, Recent Activity, Favorite, Hidden, Install Size, Installation Folder, Installation Status, Release Date, Date Added, Date Modified, Version, Community/Critic/User Score, Developer, Publisher, Platform, Genre, Library). Sorting uses `ListCollectionView.CustomSort` with a pure, unit-tested `GameSortComparer`; reference entities sort by resolved display name. Empty/unset values always sort last, regardless of direction.
- **Statistics dashboard** — launched from the sidebar button as a full-width overlay that hides the detail panel while open (before the Fase 7 overhaul it was a tab in a right-panel `TabControl`). Replicates Playnite's Overview: library counts with percentages (All/Installed/Not installed/Hidden/Favorite), total/average play time, completion status (Not played/Played), and a Top Play Time list.
- **Automatic Steam play action** — a Steam-imported game with no configured `GameAction` launches via `steam://rungameid/{appid}` passed to `steam.exe -silent` (the same approach Playnite's Steam addon takes for Steamworks-DRM games, never the local `.exe`), tracked by directory (watch processes running from the game's `InstallDirectory`). Resolution logic is pure and unit-tested in `Bridge.Import/Steam/SteamPlayActions.cs`.
- **Developers/Publishers/Platforms shown in the detail panel** — metadata is now resolved to real `Company`/`Platform` entities and displayed under the install directory (labels collapse when empty). Steam platform slugs (`pc_windows`/`macintosh`/`pc_linux`) now map to readable names (`Windows`/`macOS`/`Linux`).
- **Local Steam artwork in the library** — icons, covers and hero backgrounds are read from Steam's local `appcache\librarycache\{appid}\` cache (32x32 clienticon, `library_600x900.jpg`, `library_hero.jpg`) the moment a game is imported/loaded, so a fresh install shows complete art for every Steam game without waiting on the web metadata — resolved by `Bridge.Import/Steam/SteamLocalIconResolver.cs` and applied by `MainViewModel.ApplySteamLocalArtwork` (local art wins over web URLs). Games without a cached file fall back to the `header.jpg`/cover URLs from metadata.
- **Scan Automatically (Add Game Installed)** — `ScanInstalledWindow` + `InstalledGameDetector` detect games installed on the PC that aren't in a library: start-menu shortcuts (`.lnk`), a recursive folder scan (`.exe`/`.bat`/`.lnk`), or a single browsed executable — with installers/redists/engine helpers filtered out and the exe icon shown in the picker.
- **Web image search in the game editor** — `ImageSearchWindow` + `WebImageSearchService` (DuckDuckGo image endpoint, no API key) let you search for and pick Icon/Cover/Background art directly in the editor's Media tab.
- **Formatted descriptions** — Steam descriptions are parsed into typed blocks (headings, subheadings, bullet lists, interleaved images) and rendered with their HTML structure instead of a flat text dump.
- **Runtime theme switching** — `ThemeManager` + `ThemeColorWindow`: 9 accent presets plus a custom picker; the whole palette is recalculated from the accent and persisted to `theme.json`.
- **Playnite-style manual game editor** — "Add Manually" opens the shared `GameEditWindow` in New-Game mode; it now has Sorting Name, per-field create-on-the-fly reference buttons (Genre/Developer/Publisher/Platform) and Browse/Search-web art pickers.

### Changed
- **Fase 7 — WPF-UI 4.3.0 visual overhaul.** The shell was rebuilt on WPF-UI: `FluentWindow` with Mica backdrop, a 3-zone `TitleBar` (search, view-mode toggles, overflow menu with the global actions), and a 52px icon **sidebar** (Library / Statistics, collapsible and re-positionable). All views share one dark token palette (`Bridge/Styles/Theme.xaml` — indigo family, Inter Variable font, #007ACC UI accent) with **runtime theme switching** (9 color presets + custom picker, persisted to `theme.json`). Post-overhaul baseline: ~2.6s cold start / ~180MB RAM (see DEVELOPMENT.md). Details in [ADR-3](ARCHITECTURE.md#adr-3-wpf-ui-430-for-the-visual-overhaul-supersedes-the-original-plain-wpf-first-adr).
- `LibraryStatistics` extended with `PlayedCount`/`NotPlayedCount`, `TotalInstallSizeBytes` and human-readable display strings; the ViewModel now exposes the whole object as `Statistics` instead of only a status-bar line.
- Global actions moved out of the main page into the title bar overflow menu (Add Game with Import from Steam / Add Manually / Scan ROMs / Scan Automatically, Support, Sidebar, Theme, Settings, About, Exit; Configure Emulator and IGDB Settings under Settings) — a `File`/`Tools` menu bar before the Fase 7 overhaul. Add Manually opens the `GameEditWindow` in "New Game" mode (no separate `AddGameWindow`); Scan ROMs uses a dedicated prompt dialog (`ScanRomWindow`).
- Game detail panel reorganized: playtime, install directory, save/delete/download buttons, and the Play button now sit in the right column beside the cover; only Description and Background remain below.
- "Set Play Action" field removed from the UI - the Steam play action is resolved automatically; the leftover `SetPlayActionCommand`/`ExecutablePathInput` ViewModel code was removed entirely.

### Fixed
- Transient runtime flags (`IsInstalling`/`IsUninstalling`/`IsLaunching`/`IsRunning`) are reset to `false` on every load from the database — a crash or forced close mid-game no longer leaves a game stuck shown as "running" on the next launch (previously the reset was documented as `Bridge.Storage`'s responsibility but never implemented).
- Steam directory-based playtime tracking now gives up after 5 minutes if the game never spawns a process in its `InstallDirectory` (instead of tracking forever with `IsRunning` stuck true), and only counts the session from the moment the game's process actually appears.
- Release date display no longer renders a dangling hyphen (`2026-08-`) when only the year and month are known.
- Removed dead code: unused `FormatField`, unused `HttpClient` field in `ImageUrlConverter`, the ComboBox-era `EnumValues`/`EnumDescriptionConverter`/`BoolToIndexConverter` (registered in XAML but bound by nothing), and unused `SteamSearchEntry`. Empty JSON list columns now round-trip as empty lists instead of `null`.
- Security: pinned `SQLitePCLRaw.bundle_e_sqlite3` 3.0.3 in `Bridge.Storage` to fix CVE-2025-6965 (GHSA-2m69-gcr7-jv3q, high) — the transitive `lib.e_sqlite3` 2.1.11 bundled vulnerable SQLite 3.49.1, now replaced by SourceGear.sqlite3 3.50.4; verified by the EF Core round-trip tests.

## [0.1.0] — 2026-08-06

### Added
- **Core (Fase 1-2):** .NET 10 / WPF shell with list + detail views; manual add/edit of games; entities, contracts and `BridgeDbContext` (EF Core + SQLite); repository layer (`IRepository<T>`, `GameRepository`).
- **Manual edit & import (Fase 3):** create/edit/delete, favorite/hidden flags; launch a game via its `GameAction` and track playtime with a poll-based monitor (`Bridge/Services/GameLauncher.cs` — only `GameActionType.File` and `GameActionType.Emulator`, exact launched PID tracked).
- **Statistics (Fase 4):** playtime/playcount/last-activity tracking and basic library statistics.
- **Steam import:** `Bridge.Import` with `SteamLibraryImporter`, `SteamPaths`, hand-rolled `VdfParser` (ADR-11); registry → `libraryfolders.vdf` → `appmanifest*.acf`, `StateFlags=4` filter. Auto-import on startup — Steam games are detected automatically without clicking a button.
- **Emulation (Fase 6):** `Bridge/Services/RomScanner.cs` (folder scan by extension, dedup by exact path — no CRC/DAT yet); emulator setup UI; `GameAction(Emulator)` launch with `{RomPath}` substitution.
- **Metadata (Fase 5):** `Bridge.Metadata` with `IgdbMetadataProvider` (ADR-10). `IGameMetadataProvider` interface for multi-provider support.
- **Steam Store metadata:** `SteamMetadataProvider` — HTTP-anonymous metadata from the official Steam store (no login, no API key); maps Name, Description, ReleaseDate, CoverImage, BackgroundImage, CriticScore (Metacritic), CommunityScore (SteamDB formula), Developers, Publishers, Genres, Platforms, Features and Links.
- **Auto-metadata on import:** newly imported Steam games automatically receive metadata from the Steam Store on startup — no manual action needed.
- **Multi-provider fallback:** "Download Metadata" tries IGDB first, then falls back to Steam Store. Steam-imported games use their AppID for a guaranteed direct lookup.
- **Revamped detail panel:** cover image, release date, critic/community scores, background image, and install directory now visible in the UI.

### Changed
- Dedup key is `(ExternalId, SourceId)` instead of Playnite's `(GameId, PluginId)` (ADR-6).
- Single `Company` entity covers developer/publisher roles (ADR-7); metadata uses plain IDs instead of `MetadataProperty` (ADR-8).

- Multi-mode process tracking (ProcessName, OriginalProcess) and Script game action types — only File/URL/Emulator are implemented; Directory tracking covers Steam/Epic plus protected launchers via executable-name matching (added 2026-08-14), and process-tree tracking covers File/Emulator actions via `ProcessTreeSnapshot`/`ProcessTreeExpander`.
- `SoftwareApps`, `ImportExclusions` collections (basic `FilterPresets` now exist — All/Favorite/Most Played/Recently Played — as list presets, not yet as a persisted collection).
- `SkipExistingValues` semantics (metadata downloads unconditionally overwrite).
- Bundled "known emulator" catalog (profiles are user-configured only; see `EmulatorProfile`).
- Full emulation DAT/CRC matching (ROM scanning is filename + extension based).
