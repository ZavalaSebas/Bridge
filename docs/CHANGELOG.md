- **Organize ROMs** — On import (and from Settings → Organize ROMs), files under the scan folder are moved into per-platform directories and renamed to the official DAT title. Sidecar SRAM next to the ROM moves with it.
- **Statistics history** — play sessions and completion timestamps (`CompletedAt`, `PlaySessions` on `Game`, `GamePlaySession` entity) power a new completion board, historical timeline and persisted session history in the statistics dashboard (`LibraryStatistics`, migration `AddStatisticsHistory`, `MainViewModel.Games.cs` sets `CompletedAt`).

## [0.3.0] - 2026-08-18

### Added
- **AppData migrator** — numbered startup migrations for settings files and folder layout under `%LOCALAPPDATA%\Bridge\` (`appdata-version.txt` tracks applied steps). v1 ensures standard folders, merges legacy `ImageCache/`, rewrites Grid→Covers keys, protects IGDB settings with DPAPI, and removes obsolete paths — so updates can reshape AppData without manual cleanup. Covered by `AppDataMigratorTests`.
- **Bridge branding** — custom app icon and logo in the menu button and About hero; credits Erick Nuñez for artwork.
- **Status bar progress for long metadata operations** — metadata sync and related flows report determinate progress in the status bar instead of a static message.
- **Zero-setup emulation: Bridge installs and manages its own RetroArch** — `Bridge.Emulation/RetroArchService.cs` resolves the newest official RetroArch release (version from the GitHub release tag, archive from Libretro's buildbot as `stable/{version}/windows/x86_64/RetroArch.7z`), downloads it with a determinate progress bar in the status bar, extracts it with SharpCompress (solid-7z extraction streams in one forward pass via `WriteToDirectory`, ~25s for the ~200 MB / 14.8k-file build, on a pool thread so the UI never freezes), and swaps it into place atomically (staging dir + `.old` backup) with a `retroarch.version` marker as the change signal. Cores are installed on demand from the buildbot nightly as `{core}_libretro.dll.zip`. A `SemaphoreSlim` serializes installs so two quick Plays can't extract over each other, and a startup cleanup removes leftover staging/`.old`/partial-download artifacts from a crashed install. See `RomPlatformCatalog` for the supported systems.
- **Curated platform→core catalog** — `Bridge.Emulation/RomPlatformCatalog.cs` maps 15 systems (NES, SNES, N64, GB, GBC, GBA, NDS, Genesis, Master System, Game Gear, Atari 2600/7800, PC Engine, Lynx, WonderSwan) to their Libretro core DLLs and ROM extensions, so a scanned ROM knows which system it belongs to and which core it needs.
- **The Play button adapts to the install state** — for a managed ROM, the button reads **Download** when RetroArch or the required core isn't installed, **Downloading…** while the install runs (with the status-bar progress bar), and **Play**/**Stop** once ready or running — driven by `MainViewModel.PlayButtonText`/`PlayButtonSymbol`/`PlayButtonIsStop` (which also track `Game.IsRunning` via a `PropertyChanged` subscription). Scanning a ROM folder now auto-selects the first imported ROM.
- **ROM scanner rebuild** — `RomScanner` now scans **recursively**, recognizes systems from the extension via `RomPlatformCatalog` (no longer tied to a single emulator profile), skips companion files (`.sav`, `.srm`, `state\d+`, `ss\d+`), creates the managed "Bridge RetroArch" `GameAction`, and adds `ToSearchName` — an IGDB-friendly name normalization (strips region/version tags, drops separator hyphens: "Pokemon - Emerald Version" → "Pokemon Emerald Version") so ROM metadata matches IGDB titles. `ScanRomWindow` dropped its emulator/profile pickers accordingly (Bridge manages RetroArch itself).
- **Metadata network handling** — all four metadata flows (manual Download Metadata, post-scan import, and the two startup syncs) now detect a missing network connection (`NetworkInterface.GetIsNetworkAvailable`) and show *"No internet connection. Metadata will download the next time Bridge opens with a connection"* instead of a misleading "No metadata found"/"no updates"; the startup syncs retry automatically on next launch by design.
- **Managed emulator settings window** — `EmulationSettingsWindow` + `EmulationSettingsViewModel` replace the old manual emulator setup for the managed RetroArch path: it shows the install/core status and a "Check for updates" action (`UpdateInstalledAsync`) that refreshes the frontend and all cores to the latest.
- **Self-updater** — `Bridge/Services/AppUpdateService.cs` checks GitHub Releases (`ZavalaSebas/Bridge`) against the assembly version: silently at startup (so updates are found without asking) and on demand via a new **Check for updates…** item in the app menu. When a newer release exists, it confirms, downloads the `Bridge.exe` asset (HTTPS only, GitHub hosts allowlisted, 256 MB cap, byte-count progress on the status bar), and applies the safe swap from DEVELOPMENT.md — running exe → `.old`, downloaded → current, restart. **An update handshake makes the swap survive a broken new build**: the `.old` is kept as a rollback copy until the new exe proves it starts (`ConfirmUpdateApplied` after the window shows); if startup fails, `RollbackToPrevious` restores the previous exe and relaunches it. The library DB is backed up to `bridge.db.bak-update` before each update (manual-recovery net, not auto-restored). "Not now" on the confirm dialog keeps the update pending: a download button appears next to the random-game button (tooltip with the pending version) and applies it on click. Updates only apply to the published single-file build (`CanSelfUpdate`); dev/`bin` runs are left alone. Covered by `AppUpdateServiceTests`.
- **Message dialogs redesigned to match the app** — `MessageDialogWindow` went from a floating borderless card to a proper `FluentWindow` (Mica, `ExtendsContentIntoTitleBar`, real title bar with close button, themed buttons), matching the About/editor windows instead of looking like a detached box. `ShowConfirm` gained `confirmText`/`cancelText` so the update dialog can say "Update"/"Not now" instead of "OK"/"Cancel".
- **Beta/pre-release update channel** — the updater now reads the full GitHub releases list (`/releases?per_page=100`, newest first) instead of `/releases/latest`, and offers releases according to the **update channel**: **Stable** (the default) skips GitHub prereleases, **Beta** accepts them. The choice persists in `update-channel.txt` (`UpdateChannelSettingsStore`) and is toggled with a "Receive beta builds" switch in the About window. Tags are compared by numeric prefix (`v0.3.0-beta1` parses as `0.3.0`), so a beta never downgrades a user on the same-numbered stable — the GitHub `prerelease` flag, not the tag text, decides channels. When a stable user is up to date but a newer prerelease exists, the check tells them the beta is waiting and where to enable it. Covered by `AppUpdateServiceTests` (stable skips prereleases, beta accepts them, no-downgrade rule, beta hint).

Hovering the cover slides it into view (180ms ease-out) so it can be clicked; once favorited it stays visible and fills in gold (`SymbolIcon.Filled`), unchecking while not hovering tucks it back away. Clicking it plays a short bounce "pop" (0.5→1.35→0.9→1.0 over ~380ms), and a 250ms debounce + `IsHitTestVisible` toggle prevents the star from flickering near the cover's edge.
- **The hero Play button becomes Stop while a game runs and kills it** — `Game.IsRunning` now raises `PropertyChanged` (like `Favorite`), so the Details hero's button switches between **Play** (icon+text) and **Stop** (fixed light-red `Bridge.StopBrush`) via a DataTrigger, binding to `PlayGameCommand` or the new `StopGameCommand`. `GameLauncher.Stop(game)` kills the running processes: for directory-tracked games (Steam/Epic/launchers) it kills every process under the install directory (path + executable-name fallback for elevated launchers), for tree/exact-tracked games it kills the launched PID's expanded process tree. Stop also cancels the tracking loop so the session finalizes immediately (`GameStopped` → `IsRunning=false`) — the button always reverts to Play even if the kill fails. **Fixes for fast-play/quick-stop races**: the process-tree tracker's wait-for-launch is now a poll loop (a single check ended the session before the game appeared), if Stop is pressed before the game's process has spawned a 15s background `KillWhenAppearsAsync` watcher kills it the moment it appears (otherwise the game opened right after Stop, untracked and unstoppable), and the idle grace period is now **launch-aware**: 20s while the session is under 30s old (a gap right after Play is the launcher still spawning the game — slow right after the app starts, which used to cut the session a few seconds in), dropping to 5s once the game has been running so the close is still detected quickly. Applied to both directory and process-tree tracking.
- **Launching a game during the startup metadata sync no longer flips the Play/Stop button back to Play** — `GameRepository.ResetTransientFlags` ran on every `GetAll`/`Get`/`FindByExternalId`, and the background metadata sync calls `GetAll` right after a game starts, resetting its live `IsRunning` flag to false (and re-persisting it) — the hero button snapped back to Play mid-game even though the tracking kept running. `IsRunning` is now excluded from `ResetTransientFlags` (it's a live launcher flag); the stale-`IsRunning` crash recovery (a prior session force-closed mid-game) moved to `MainViewModel.LoadGames`, which runs once at startup before the user can launch anything. Test updated to assert `IsRunning` is preserved on `GetAll`.
- **Startup selects the last played game instead of always the first** — `MainViewModel.SelectInitialGame` picks the game with the most recent `LastActivity` (persisted when a game is launched) so reopening Bridge resumes where you left off; on a completely fresh library (nothing played yet) it falls back to the first game. Pure helper, unit-tested in `ViewModels/MainViewModelInitialSelectionTests.cs`. **Fixed two follow-up bugs**: `RefreshListDisplay` now captures the selected game *before* removing it from the collection (the RemoveAt fired `CollectionChanged` and WPF cleared `SelectedItem` → `SelectedGame` became null before the old `if (SelectedGame == game)` check, so re-imports and the metadata sync dropped the selection a moment after it appeared); and on a truly first run (empty DB) the initial selection now runs again after the startup imports populate the library.
- **Epic games now get their screenshot gallery from IGDB** — the own Cloudflare Worker now requests `screenshots.image_id/screenshots.url` on its game query, and `BridgeIgdbProvider` maps them to `GameMetadata.Screenshots` (upgraded to `t_1080p`, same as Steam's `path_full`), so the Details gallery appears for Epic/IGDB games too instead of only Steam ones.
- **Steam games import their real playtime** — `SteamLocalPlaytimeResolver` reads Steam's locally-recorded playtime from `userdata\{steamid}\config\localconfig.vdf` (`Playtime` in minutes + `LastPlayed` unix under `Software\Valve\Steam\apps`), merged across accounts (max playtime, latest activity). `SteamLibraryImporter` fills it into the imported metadata, and the import applies it on new games and merges it on existing ones (never shrinks what Bridge already tracked). Zero-config, local-only, matching ADR-11 — same philosophy as the Steam local artwork resolution.
- **The More menu toggles favorites and drops the no-op Save Changes** — "Save Changes" only re-persisted already-saved data, so it's gone; the menu now shows a dynamic **Add to Favorites / Remove from Favorites** entry (`ToggleFavoriteCommand`) that persists immediately and stays in sync with the hero star. `Game.Favorite` now raises `PropertyChanged` (the entity implements `INotifyPropertyChanged` for that one property) so a programmatic toggle updates the bound star.
- **Edit button only appears when hovering More/Edit, not Play** — the hero's Edit button now reveals on the `MoreEditHost` (the More+Edit group) instead of the whole button row, so hovering over Play (or the area to its left) no longer pops Edit out.
- **The hero Play button has a press animation** — clicking it sinks the button to 0.92x then bounces back to 1.0x (`BackEase`), on top of the existing hover scale; the button is also `Focusable="False"` so clicking Play no longer steals keyboard focus from the list.
- **Closing a game no longer deselects it** — `OnGameStopped` re-renders via `GamesView.Refresh()` + `RebuildDetailedRows()` + re-asserting `SelectedGame` instead of removing/re-inserting the game from the collection (which dropped the ListBox selection).
- **Launcher-based games keep tracking after the launcher exits** — Genshin (and other launcher-driven games like Epic/GOG frontends) launch a small `launcher.exe` that spawns the real game and closes; Bridge used to track only the launched PID, so the session ended the moment the launcher died (~5s). File/Emulator play actions now use **process-tree tracking** (`ProcessTreeSnapshot` enumerates every process + its parent via the Win32 Toolhelp32 API; `ProcessTreeExpander` + `TrackProcessTreeAsync` keep the launched process *and every descendant* in the tree each poll, pruning dead ones) — the launcher exiting no longer ends the session, which survives until the real game closes. Pure tree logic is unit-tested in `ProcessTreeExpanderTests`; the OS snapshot was verified end-to-end with a real launcher→child process pair.
- **Directory tracking handles protected launchers and UAC gaps (Genshin)** — Genshin's real launcher (`HYP.exe`/`HYPHelper.exe`, HoYoPlay) runs elevated. Two fixes: (1) `Process.MainModule.FileName` *throws* (Win32 access denied) for elevated processes instead of returning null, so the original single try/catch swallowed the exception and the name-fallback never ran — the path is now read in its own try/catch, and when unreadable the process is matched **by executable name** against the install directory's `.exe` files (recursive, built once per session), matching by executable name against the install directory; (2) an already-launched session only ends once the directory stays empty for a **10s idle grace period** (`DirectoryIdleTimeout`), covering Genshin's UAC relaunch (the non-elevated launcher exits while the user approves the admin prompt, then relaunches elevated) — otherwise the session lasted only as long as the user took to approve the UAC. The name fallback was verified live against the running HYP processes (all 5 matched).

### Fixed
- **Covers view no longer stacks into a single column** — the Grid view could show every cover in one centered column instead of wrapping into a wall. Two causes: (1) `CenteringWrapPanel` first measured while the views column was still at the List-view width (360px) and kept that one-column wrap until something else invalidated layout — fixed by re-measuring on `SizeChanged`; (2) with grouping active, WPF's default `GroupStyle` panel is a vertical `StackPanel`, so covers inside each group ignored the ListBox's `CenteringWrapPanel` — fixed by setting `GroupStyle.Panel` to the same panel on `CoversList`. Verified on a fresh library and with grouping enabled.
- **The startup metadata sync no longer re-downloads what's already there** — previously a Steam game with a description but a missing IGDB social link was re-downloaded *in full* from the Steam API on every app open (just to fetch the link). `DownloadMissingSteamMetadataAsync` now splits the work: games missing a description get the full Steam metadata (+ IGDB links); games that already have a description only get a light IGDB call for the missing social links. `ApplyMetadata` also gained an `overwrite` flag — the manual "Download Metadata" action still refreshes every image, but the automatic sync (`overwrite: false`) only fills cover/background/screenshots that are missing, keeping already-downloaded art stable.
- **Steam-imported games are read-only in the editor except their artwork** — `GameEditViewModel.IsSteamManaged` (an appid as `ExternalId`, non-manual) drives the edit window: the General and Details tabs are hidden entirely and only the Media tab shows (icon, cover, background — with Browse/Search web still working). `Save()` writes back only the three artwork fields for Steam games; metadata (name, description, scores, genres, ...) stays managed by the startup sync. Epic and manual games keep full editing. A banner explains the restriction.
- **Directory tracking handles protected launchers and UAC gaps (Genshin)** — Genshin's real launcher (`HYP.exe`/`HYPHelper.exe`, HoYoPlay) runs elevated. Two fixes: (1) `Process.MainModule.FileName` *throws* (Win32 access denied) for elevated processes instead of returning null, so the original single try/catch swallowed the exception and the name-fallback never ran — the path is now read in its own try/catch, and when unreadable the process is matched **by executable name** against the install directory's `.exe` files (recursive, built once per session), matching by executable name against the install directory; (2) an already-launched session only ends once the directory stays empty for a **10s idle grace period** (`DirectoryIdleTimeout`), covering Genshin's UAC relaunch (the non-elevated launcher exits while the user approves the admin prompt, then relaunches elevated) — otherwise the session lasted only as long as the user took to approve the UAC. The name fallback was verified live against the running HYP processes (all 5 matched).

## [0.1.0] — 2026-08-06

### Added
- **Core (Fase 1-2):** .NET 10 / WPF shell with list + detail views; manual add/edit of games; entities, contracts and `BridgeDbContext` (EF Core + SQLite); repository layer (`IRepository<T>`, `GameRepository`).
- **Manual edit & import (Fase 3):** create/edit/delete, favorite/hidden flags; launch a game via its `GameAction` and track playtime with a poll-based monitor (`Bridge/Services/GameLauncher.cs` — only `GameActionType.File` and `GameActionType.Emulator`, exact launched PID tracked).
- **Statistics (Fase 4):** playtime/playcount/last-activity tracking and basic library statistics.
- **Steam import:** `Bridge.Import` with `SteamLibraryImporter`, `SteamPaths`, hand-rolled `VdfParser` (ADR-11); registry → `libraryfolders.vdf` → `appmanifest*.acf`, `StateFlags=4` filter. Auto-import on startup — Steam games are detected automatically without clicking a button.
- **Emulation (Fase 6):** `Bridge.Emulation/RomScanner.cs` (folder scan by extension, dedup by exact path — no CRC/DAT yet); emulator setup UI; `GameAction(Emulator)` launch with `{RomPath}` substitution.
- **Metadata (Fase 5):** `Bridge.Metadata` with `IgdbMetadataProvider` (ADR-10). `IGameMetadataProvider` interface for multi-provider support.
- **Steam Store metadata:** `SteamMetadataProvider` — HTTP-anonymous metadata from the official Steam store (no login, no API key); maps Name, Description, ReleaseDate, CoverImage, BackgroundImage, CriticScore (Metacritic), CommunityScore (SteamDB formula), Developers, Publishers, Genres, Platforms, Features and Links.
- **Auto-metadata on import:** newly imported Steam games automatically receive metadata from the Steam Store on startup — no manual action needed.
- **Multi-provider fallback:** "Download Metadata" tries IGDB first, then falls back to Steam Store. Steam-imported games use their AppID for a guaranteed direct lookup.
- **Revamped detail panel:** cover image, release date, critic/community scores, background image, and install directory now visible in the UI.

### Changed

- Single `Company` entity covers developer/publisher roles (ADR-7); metadata uses plain IDs instead of `MetadataProperty` (ADR-8).
